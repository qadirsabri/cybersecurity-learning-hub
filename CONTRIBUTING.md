# Working together: learner and mentor

**Repository owner / mentor:** Maintain the overall plan, review evidence, comment on Issues, and suggest realistic adjustments.

**Learner:** Work from her own GitHub account, claim monthly Issues when access is granted, complete labs and projects, attach evidence, and close Issues after review.

## Monthly workflow

1. Open the Issue for the current month and read its checklist.
2. Spend roughly 1 hour on concepts, 1.5 hours on guided labs, and 1 hour on practice, code or documentation each week.
3. Post a short progress comment with what was learned, a safe link to code or notes, and any blockers.
4. Commit practical work using a verified email associated with the learner's GitHub account.
5. Mentor reviews the evidence; the Issue can be closed when the goals are met.

**Status:** Open = planned or in progress; Closed = completed. Add comments for blockers or deferrals.

**Privacy and ethics:** Use only authorized training environments and synthetic/public datasets; never post passwords, tokens or sensitive data.

**GitHub Projects:** Once a GitHub Project is created in the web interface, add these Issues to it and configure a Roadmap view with date fields. The repository itself and its Issues are ready to use independently.
